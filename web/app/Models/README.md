# مدل‌ها (`app/Models`)

هر فایل یک جدول پایگاه داده است، به شکل کلاس PHP. ساختار جدول‌ها در [`../../database`](../../database/README.md) است.

## فایل‌ها

| فایل | جدول | کار |
|---|---|---|
| `Product.php` | `products` | محصول: نام، کد مدل یکتا، برند، دسته، وضعیت (منتشرشده / پیش‌نویس)، منتخب، توضیحات، کشور سازنده، **قیمت داخلی** (فقط پنل). حذف نرم با پاک شدن خودکار پس از ۳۰ روز. پس از هر ذخیره، کش منوی کاتالوگ و پنل پاک می‌شود. |
| `Category.php` | `categories` | دسته‌ها به شکل درخت (۲ گروه مادر و ۱۴ دسته)، آیکون و نقاشی جای عکس. |
| `CategoryAttribute.php` | `category_attributes` | فیلدهای مخصوص هر دسته (مثلاً «ابعاد قاب» تاچ پنل)، نوع (انتخابی، چندانتخابی، عدد، بله/خیر، متن)، فیلتر بودن و «لازم برای انتشار». |
| `AttributeOption.php` | `attribute_options` | گزینه‌های فیلدهای انتخابی، با رنگ نمونه برای فیلتر رنگ. |
| `ProductValue.php` | `product_values` | مقدار هر فیلد برای هر محصول. |
| `ProductCustomSpec.php` | `product_custom_specs` | «مشخصات دلخواه»: ردیف‌های آزاد عنوان و مقدار. |
| `Brand.php` | `brands` | ۱۰ برند، فعال یا غیرفعال. |
| `Protocol.php` | `protocols` | KNX، Zigbee و Modbus فعال؛ IP و Wi-Fi غیرفعال و فقط در پنل. |
| `Media.php` | `media`، `product_media` | عکس (WebP) و دیتاشیت، با ترتیب و نقش. |
| `Need.php` | `needs` | «نیازها» برای راهنمای انتخاب (روشنایی، پرده، دما…) و دسته‌های مرتبط با هرکدام. |
| `ShowcaseProject.php` | `showcase_projects` | پروژه‌های اجراشده، برای وقتی که عکس‌ها برسند. |
| `Inquiry.php` / `InquiryItem.php` | `inquiries`، `inquiry_items` | هر کلیک «ارسال در واتساپ»: متن پیام، نام و پروژه اختیاری، اقلام و تعداد، با نسخه‌ای از نام و کد محصول در آن لحظه. |
| `ProductUpdate.php` | `updates` | هر به‌روزرسانی از فایل: تحلیل، گزارش، مسیر پشتیبان، وضعیت. فقط آخرین به‌روزرسانی اعمال‌شده قابل بازگردانی است. |
| `Setting.php` | `settings` | تنظیمات (واتساپ، قالب پیام، تماس، سئو، رمز بسته `.fritz` رمزشده با `APP_KEY`)، با کش. |
| `User.php` | `users` | کاربر پنل با نقش `admin` (مدیر کل) یا `editor` (ویرایشگر محتوا) و وضعیت فعال/غیرفعال. |

## انجام‌شده
- همه جدول‌های طرح `docs/PLAN.md` ساخته و به هم وصل شده‌اند.
- محصول پیش‌نویس هیچ‌جای کاتالوگ عمومی دیده نمی‌شود (`Product::catalog()`).

## باقی‌مانده
- مدل `UserInvite` برای جدول آماده `user_invites` (دعوت کاربر با لینک).
- مدل گزارش فعالیت (`activity_log`) فعلاً مستقیم با کوئری خوانده می‌شود؛ با ساخت صفحه «گزارش فعالیت» مدل جدا لازم می‌شود.
